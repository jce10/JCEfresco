# Repeated `--curve` and custom-label update

## User-facing syntax

Each explicit curve uses:

```text
MODEL:STATE_FILE[:SCALE[:LABEL]]
```

The label is the fourth field and may contain spaces when the complete argument
is quoted:

```bash
--curve 'cc:state4.txt:10.0:2d3/2 component (x10)'
```

## Files changed

### `src/jcefresco/cli_plot.py`

- Added repeatable `--curve` command-line arguments.
- Added `parse_curve_spec()` to parse the model, state file, scale, and label.
- Allows the same model to appear more than once with different `state*.txt`
  files, scales, and legend labels.
- Rejects ambiguous combinations of `--curve` with the older model-keyed
  options (`--models`, `--scales`, `--labels`, and `--state-files`).
- Prints each resolved curve before plotting.

### `src/jcefresco/plotting/plot_ad.py`

- `FrescoCurve` stores an optional label for every individual curve.
- `plot_label()` uses that custom label in the legend.
- Non-unit scale factors are appended to the displayed label automatically.

### `tests/test_smoke.py`

- Added tests for multiple curves from one model.
- Added checks that custom labels and scale factors survive parsing.
- Added a check of the final legend label generated by `plot_label()`.

### `README.md`

- Documented repeated `--curve` usage.
- Added examples with custom labels and scale factors.
- Explained when to use `--curve` versus the original one-curve-per-model CLI.

## Files not changed

No changes were needed in the FRESCO parser, YAML configuration, reaction
configuration, or the thin `scripts/plot.py` wrapper.
